# ARE YOU HUMAN? — 記憶・制作・生活の実装計画

## 目的と完成条件

4人の住民に独立した長期記憶と制作活動を持たせる。プレイヤーが受動的でも制作、講評、修正が進み、Labで制作物を見たり聴いたりでき、結果が街に残る。友情・警戒・崇拝等の結末は指定しない。

最初の縦切りはポスターと短い曲。5分間で着手、試作、講評、修正または保留、公開のいずれかの変化が見える。未公開・失敗も有効な結果。台詞だけで作品の完成を捏造しない。

## 現状の問題

- 記憶18件、会話履歴12発言で古い内容を破棄していた。
- 保存はプロセスメモリのみで、再起動により進行が消える。
- 作業は目的地とラベルが中心で、制作物や工程の状態がない。
- 話題は直近の噂に偏り、昔の体験や制作判断を検索できない。
- 新モデルの大きなコンテキストと、住民の永続記憶は別物。モデルを変更しても記憶データは維持する。

## 実装順・依存関係

1. 個別記憶の保存・検索・訂正履歴 → 2. ディスク保存と復元 → 3. 制作案件・作品形式・講評 → 4. Labとモニター → 5. 公開物を街に反映 → 6. 5分間の受動プレイ検証。

順序を守り、各段階でテストしてから次へ進む。巨大なエージェントフレームワーク、ベクトルDB、実モデルの訓練は初期段階では導入しない。

## A. メモリ設計

### 保存と想起を分ける

各住民につき最大5,000件の出来事と最大10,000発言を保存する初期上限。保存上限とAPIへの投入量は独立。直近24発言と関連記憶最大16件・合計約6,000文字を選択する。古くても関連する情報は想起できる。上限到達は状態に表示し、無制限とは表現しない。

記録フィールド: id / owner / kind / text / source / hop / timestamp / importance / supersededBy。直接証言・目撃・伝聞・自己の制作活動を区別。事実の真偽と「誰から聞いたか」を混同しない。同じ話題の新しい証言で古い記録を消さず、置き換え履歴を保持する。

原文の長期履歴と、現在有効な記憶を別に保持する。会話原文を保存しただけで長期推論が保証されるとはしない。初版の検索は日本語の文字n-gram・英単語、重要度、直近性の組み合わせ。後で必要な場合のみ埋め込み検索を追加する。

### 個別性

他人の個別記憶はプロンプトに含めない。伝達された時だけ聞き手の記憶を作る。講評も参加者だけが覚える。公開作品の内容は公開後の閲覧で知る。関係の判断理由は本人の経験として保存する。

### 保存

セッションIDをキーにゲーム状態だけをJSONへ保存。APIキー・Authorization・接続設定は一切保存対象にしない。UUID検証、専用ディレクトリ、原子的なファイル置換、書込順序保証を設ける。保存先はGitとHTTP公開対象外。保存失敗を成功と表示しない。再起動後は同じタブのセッションIDで復元。複数タブは混同しない。

「最初から」は明示的な初期化としてディスクにも反映。モデル変更、SYSTEM UPDATEでは記憶を消さない。

## B. バックエンドの制作モデル

Project: id, owner, type, goal, phase, revisions, reviewers, feedback, publishedRevision, timestamps。

工程: draft → review → revise / hold / publish。許可された遷移だけ実行。LLMは提案と判断理由を返し、サーバーが検証・適用。進行中の案件を同じ住民が同時に更新しない。

Poster: title, subtitle, palette, layout, motif。SVG/Canvas等で安全に描画し、任意HTMLやスクリプトを実行しない。

Music: title, tempo, notes[{pitch,duration}], instrument。音域、長さ、テンポを制限。短いフレーズをWeb Audioで試聴する。生成音源サービスは必須にしない。

講評は実際の案の内容、本人の好み、作者との関係を見て行う。賛成役と反対役を固定しない。作者が採用／不採用の理由を持つ。発言と関係加点を一対一に固定しない。

## C. フロントエンド

### Lab

一人称で出入りできる小さな作業室。入口と出口を明示し、退出しても街の進行を保持する。机・椅子・モニター・試聴場所・掲示壁。初版は建物内部一室に限定。

### 住民の生活

移動、作業、講評相手のところへ移動、会話、作業に戻る状態を分ける。作業姿勢・画面・短い作業音を連動。会話中に勝手に別室へ移動しない。目的地に着けなければ作業開始と判定しない。

### モニターと作品

サーバーの同じrevisionをモニター、拡大画面、掲示板に使う。現行案・旧案・作者・公開状態を表示する。作品への感想は作品ID付きで送り、NPCが別作品を見たふりをしない。曲はクリックで再生し、退出・停止で音源を止める。

### 観察UI

保存記憶件数、最近の想起内容、出典、訂正履歴、制作案件、変化の理由を表示。これは観察者向けであり住民同士に全知を与えない。履歴の検索・ページ送りを設け、大量記録を毎フレーム転送しない。

## D. スケジューラと費用

描画フレームとAI判断を分離。移動・アニメーションはローカル、意味のある状態遷移のみAPIへ送る。同じ住民の呼びかけ、会話、制作、講評は直列化。ユーザー会話を優先。タブ非表示では新規自律生成を止める。1案件・1工程につき必要な生成のみ。既存120回上限とデモ表示を共有し、上限に達した時は明示する。

## E. 検証

- 18件を超えても最初の証言を検索できる。
- 関係ない大量記録があっても関連記憶を選べる。
- 訂正前の記録は残るが現行事実として想起しない。
- 他の住民が非公開の会話を知らない。
- 再起動で復元、リセットで初期化、異なるセッションは分離。
- 保存JSON、API状態、エクスポートに設定キーが含まれない。
- 古い制作revisionへの更新を拒否。公開前は街の掲示を変えない。
- 5分受動プレイで住民の活動と作品の変化を確認。
- Labの出入り、会話による中断、衝突、画面サイズ変更、試聴停止を実画面確認。

## 工数の目安（実装・検証を含む概算）

個別記憶と永続化 3〜5時間 / 制作状態と生成 4〜6時間 / Labと作品表示 5〜8時間 / 街への公開と受動進行 3〜5時間 / 統合調整 2〜4時間。
合計17〜28時間程度を初期見積もりとし、最初のポスター一本が動いた時点で更新する。アセットの精緻化や長時間シミュレーション評価は別枠。

## 今回の着手範囲

まずA（個別記憶・検索・保存復元）を実装し、制作・Labが依存する土台を固める。後続項目は未実装のまま完成と扱わず、段階ごとに状態を報告する。

## 実装状況（今回）

実装済み: Aの個別記憶・検索・訂正・保存復元、ポスターと曲の試作/講評/判断、LabとLibraryの一人称室内、モニターと試聴、公開ポスターとカフェ音楽、作品への感想の記憶。

初期案からの制限: Labはコードで作った一室で専用アセットは未導入。住民の移動は室内外の入口を経由する簡易方式。研究案件を無限に発案する仕組みではなく、まず2案件。作品は静的なレイアウトと短い音列で、外部画像/音楽生成は使わない。関係変化は既存会話の評価と記憶を利用し、講評専用の細かな感情評価は後続。

検証: 自動テスト18件。UIでLibrary/Labの出入り、資料表示、ポスター/曲表示、試聴/停止、保存した街の再開を確認。
