# あなたから変わる街 — playable iteration

タイトルの「この街に、来てみる」が新しいメインの入口。陽菜の住民と街の雰囲気を引き継ぎ、人間の到着から一人称で遊ぶ。Miaのカフェのエピソードと自由な街も別の入口で残している。

## 最初の一周

1. 住人が人間を見つけて振り返る。目の前の分配器を **E** で切り替えると、光の流れ・街の灯り・住人の反応がすぐ変わる。
2. 配分は「中央」「街」「半分ずつ」。中央の電力と冷却を維持すると、形の違う6棟が段階的に現れる。街へ分けた電力は共同作業に使える。
3. **明日のスケッチ** に自由な案を書く。住人一人が案を解釈して協力者を選び、その相手が別のAPI呼び出しで参加を判断する。引き受けない場合もある。
4. 二人が現地へ歩き、電力を使って12秒間一緒に作業する。会話で足止めした住人は作業に加わらない。完成すると他の住人も見に来る。
5. 完成した庭・遊び場・星を見る場所は、近づいて触ると音と光が返る。次の案は川辺、木立へ広がる。風のオルガンは8秒間、両方の電力を増やす。繰り返し鳴らすには5秒必要。
6. 中央でRealtime会話。「街の更新を止めて／再開して」で実際の進行が変わる。近くの住人との通常会話も、生成された返答をTTSで聴ける。

同期中に自分だけ動ける場面、中央のホログラム、橋の奥の記憶の都市を追加した。新しい遊びと通行の修正は [自分だけが人間](HUMAN_TOWN.md) を参照。

WASDで歩く、Shiftで小走り、Spaceで短いダッシュ。クリック後はマウスで見回し、Escでカーソルを戻す。設定から感度と画面の揺れを調整できる。近い住人がいる場合、Eは会話を優先する。住人から少し離れて遊具を見ると、Eの対象が切り替わる。スケッチと設定は右上のメニューから開く。Mで街を見渡せる。

## AIの担当範囲

- **Responses / gpt-5.6-luna**: 提案の解釈、名前、協力者、相手の承諾・拒否、会話。応答速度を優先。候補地、移動、建設時間、電力、完成条件はゲーム側が検証する。
- **Image API / gpt-image-2.5-flare**: 合意した公開の案をプレイ中に一枚のスケッチへ生成する。低品質設定・1024角・JPEG。画像を待つ間も住人の作業とプレイは続き、届いた画像は広場のスケッチボードと相談画面に飾る。今夜3回まで。`OPENAI_IMAGE_MODEL` で変更できる。[画像生成ガイド](https://developers.openai.com/api/docs/guides/image-generation) / [Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)。
- **TTS / gpt-4o-mini-tts**: 到着と最初の操作の5つの台詞は事前生成した声。生成された住民の相談・返答は実行時に読み上げ、同じ発言はキャッシュする。声はAIが生成することを画面にも表示する。
- **Realtime / gpt-realtime-mini**: 中央とのWebRTC会話。マイクなしの文字入力＋音声出力も可能。停止・再開は既存の検証済みツール経由。通常のAPIキーはサーバー内に留める。

住人との共有可能な会話と、スケッチに出した公開提案は8秒後に中央へ届く。個別の「二人だけにして」という約束は、その住人の未送信記録を消して以降の共有を止める。公開の掲示板とは区別している。中央の学習・近代化はゲームの進行であり、モデルの重みを訓練してはいない。

3Dの成果は3種類の設計済みの部品で表現する。画像生成が任意の3D形状へ変換されるわけではない。現状は3拠点を順に使い、同じ拠点への次の案はその場所を作り替える。相談・完成の履歴は最大6件。APIなし／失敗時は定型の判断で遊べるが、生成済みと偽った画像は表示しない。完成後も街は続き、スコアや勝敗は設けていない。

## 保存と確認

ゲームは `data/sessions/`、生成した絵は `data/community-art/` に保存。進行を再開すると完成した場所・担当・資源・絵も戻る。画像本体はセッション所有権を検証して取得し、公開の静的ファイル経路には出さない。APIキー・音声通話をセーブしない。

`npm test` は物理的な到着、二人の判断、拒否、忙しい住人の所有権、資源、秘密の保持、保存・再開、画像の所有権と遅延完了、HTTP境界、移動の速度・壁抜けを確認する。

実ブラウザでは、分配器→独自の音と花の案→TomoとMiaの合意→現地作業→完成→遊具への接触→生成スケッチ表示→再読み込みから再開を確認。二つ目の自由な案ではRenとMiaが川辺の星見ドームを作り、別の絵も生成された。川辺のテーブルの角で住人が引っかかりやすかったため、作業位置に余裕を設けた。中央のRealtime接続と、文字で依頼して音声で返事を受ける経路で更新停止も確認した。マイクへの実際の発話による認識品質は今回の自動操作では確認していない。
