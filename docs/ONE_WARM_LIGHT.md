# この灯りを、明日にも。 — One Warm Light

3〜5分で遊ぶ、最初の一場面。中央の更新に電力が集まり、Miaのカフェは暖房を失っていく。一方で、Tomoは声の不調を直す更新を待っている。どちらの願いも残す方法を、プレイヤー自身が発見する。

## 遊ぶ

`npm install` → `npm start` → http://127.0.0.1:4173/ 。タイトルの「この灯りを、明日にも。遊ぶ」を選ぶ。Miaの声から始まる。

1. カフェ、中央の水、Tomo、電力を調べる。ボタンでその場所へ降りられる。
2. 気づいた方法を「思いついたことを、みんなに」に入力して相談する。住民との直接会話や、中央との文字・Realtime会話からも提案できる。
3. 住民が相棒に相談し、それぞれの持ち場に歩いて作業する。住民カードで追いかけられる。目線を借りたり直接話している間、その住民の作業は止まる。
4. 中央の更新が終わり、暖かさを維持できると、4人がカフェに帰ってくる。全員が着くとエンディング。

暖かさがなくなっても、再び温められる。急いで正解を入力する必要はない。相談の生成を待つ間は資源の進行を一時停止する。Mで街を見渡す／降りる。地上では画面をクリックしてマウスで見回し、WASDで移動。Escでカーソルを戻す。

<details><summary>実装している二つの解法（ネタバレ）</summary>

- **余熱を回す**：中央は電力8を使い続ける。カフェの電力2に回収した余熱3を足す。Shellが中央側を担当し、TomoかRenにカフェ側の管を頼む。
- **電力を分ける**：中央5、カフェ5。中央の更新速度は落ちる。Renが中央を調整し、TomoかShellに集電塔の作業を頼む。

どちらも二人の判断、現地への移動、作業完了が必要。中央を止めるだけではTomoの願いが残る。止めた場合は中央と話すか端末のボタンで再開できる。

## AIが決めることと、ゲームが決めること

`gpt-5.6-luna`（reasoning: none）が提案の意図を読み取る。主担当と相棒は別々の呼び出しで自分の事情を踏まえて協力を判断し、主担当は相棒も選ぶ。返答は構造化出力。未接続・接続失敗時は定型のデモ判断へ切り替わり、画面と会話ログに表示する。

場所、可能な仕事、電力と余熱のルール、二つの解法、主要な物語の台詞、結末は設計済み。AIが自由に工事を生成したり、会話だけで達成を宣言したりはしない。サーバーが位置・作業時間・供給・4人の到着を確認して進行を決める。中央の更新はゲーム上の表現で、モデルの重みの学習ではない。

中央のRealtime接続には `propose_cafe_plan` を追加した。中央は案を住民に届けるところまで。承諾と工事は住民の処理に引き継がれる。

## 声と見た目

- OpenAI `gpt-4o-mini-tts` で主要12台詞を生成し、`assets/episode/` に同梱。冒頭からAPI待ちなしで再生できる。声の割当・台詞・ハッシュは `manifest.json`。
- その場で生成された相談もTTSで読む。同じ発言はサーバーでまとめ、1セッションの追加音声生成は32回まで。生成失敗時も字幕とゲームは続く。
- 台詞を直したら `.env` 設定後に `npm run build:voices`。変更した台詞だけを再生成する。音声生成は会話の120回上限とは別のAPI利用。
- 陽菜の住民モデルと既存の街を使用。カフェの光とコーヒーの湯気が暖かさに応じて変化する。余熱がつながると管を光が流れ、最後にはプレイヤーの席が現れる。
- 字幕を常時表示し、AI音声であることも表示する。ミュート、台詞の再生、会話ログがある。中央との音声会話中は住民の読み上げを休止する。

## 保存と確認

エピソードを始めるたびに別のセッションを作る。以前の自由な街があるタブでは「前の街に戻る」で戻れる。再読み込み後は「保存した街の続きから」で進行・役割・会話ログを復元する。APIキーはセーブに含めない。

自動テストは資源の両立、二人の承諾、実際の到着と作業、借りた住民の停止、全員の集合、再挑戦、非公開会話、中央からの提案、保存復元、音声生成の範囲と重複抑止を確認する。全55件の自動テストが成功。Chromeと実APIで、余熱の提案からエンディング、中央の文字会話経由での電力分配からエンディング、サーバー再起動後の復元を確認済み。ブラウザのエラーログは0件。今回追加したRealtime提案ツールはサーバーテストで確認し、マイクからの提案は未検証。
