# 自分だけが人間 — 遊べる試作

陽菜の原案にある「AIだけの街に来た人間」「日常の中の違和感」を、最初の操作で見える違いにする。住人のモデルと小さな家の雰囲気を引き継ぎ、中央の奥に、都市そのものが計算しているような地区を加えた。

## 最初に試すこと

1. タイトルの「この街に、来てみる」で、新しい夜を始める。従来の分配器、相談、共同制作も遊べる。
2. 開始から約10秒で、中央の同期が住人の表情と動き、現地の作業を一時停止する。人間は歩き、目の前の住人に **E** で呼びかけられる。
3. 一人が目を開ける。その住人から近くの住人へ声と光が伝わり、全員に届くと街の灯りと共同作業を少し後押しする。離れた住人には届かない。何もしなくても同期は9秒で終わり、記憶は消えない。
4. 中央棟の正面へ行くと、常設のホログラムがこちらを向き、短い挨拶をする。Eで会話を開き、Realtimeの音声、または文字で話せる。顔は音声の再生中に口を動かす。近づくだけでマイクを起動することはない。
5. 中央の右側を回って橋を渡ると「記憶の都市」。18棟の異なる高さ・形の建物、循環する光、小さな搬送機、冷却ファン、回転する演算核がある。入口の顔の灯りにEで触れられる。メニューからも直接訪問できる。

通常画面には「街を見る」「メニュー」と、一つの状況別アクションを表示する。WASD、マウス、E、Shift、Spaceは従来通り。メニューにスケッチ、各地区への移動、音声・操作設定、街の記録をまとめた。移動ボタンはタッチ端末で表示し、デスクトップでも設定から出せる。

## 設計した部分と生成AIの役割

同期と呼び声の伝播はゲームのルール。毎秒の停止・再開をLLMへ問い合わせない。距離、現在の同期回、会話中の住人、重複した入力を検証して進行する。通常の住人との会話、二人による自由な案の相談、生成スケッチ、中央のRealtime会話は既存のAPI経路を使う。中央には実際の呼び声の成功回数と現在の街の状態を伝える。

同期開始・呼び声の達成・中央の挨拶・回廊の挨拶の4種類は、TTSで事前生成した声を追加した。呼び声を渡す短い台詞には字幕と身振りを使う。

記憶の都市の顔は4人の公開の外見を使った演出で、人格の複製・遺伝子の混合・モデルの追加学習は実装していない。搬送機は背景のアニメーションで、会話できる住人は4人。現時点の人間の特徴は「同期の外で動き、違うリズムを持ち込める」こと。食事・老化などの生存シミュレーションは今回の範囲に含めない。

## 道と入口の修正

- 道の中央にあった大きな標識をなくし、縁の短い木製道標へ変更。板全体の幅まで当たり判定を持たせた。
- 広場の中央通路を塞ぐ街灯と木を移動・整理。
- 東の住宅の階段前にあった生垣、西の住宅の入口を塞ぐカフェ席を移動。
- 生垣・低木・柵にはGLBを配置した後の実際の寸法で当たり判定を設定。柵のモデル原点のずれも補正。
- 住人の経路は障害物との線分交差を直接確認。細い角をサンプル点の間ですり抜ける問題を修正。風のオルガンの作業位置も器具の外へ出した。
- 中央裏の増築位置を移し、新しい橋への経路を確保。地面と道路は和集合から再生成し、重なった道路面を作らない。

## 確認

`npm test` は74件。同期の停止と再開、近距離での呼び声、連鎖、重複報酬の防止、作業の停止、中央の更新停止、挨拶の距離と間隔、道路の連結、薄い障害物の角を横切る経路を確認した。

`/?review=1` でゲームを開始すると、GLBを読み込んだ後の実際の当たり判定を使って31経路を確認する。住宅2軒の玄関前、Lab・Libraryの入口、中央、橋、新地区、4人×6か所の作業位置を対象にしている。これは全地点の完全な検証ではなく、今回問題になった入口・通路・作業地点の回帰確認。

実ブラウザで最初の同期中にTomoへの呼びかけ、住人の再開、中央の接近時の挨拶、Realtime接続と文字入力への音声返答を確認。中央へ更新停止を依頼し、再読み込み後も状態を復元した。マイクへの実発話による音声認識の品質は未確認。
