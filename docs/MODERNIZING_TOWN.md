# 明日のために変わっていく街

2026-09-13。「中央のモデルへ電力・水・会話の記録が集まり、可愛い街が少しずつ近代化される」方向のプレイ可能な試作。

陽菜のMia・Ren・Tomo・Shell、表情・しぐさ、元の街の素材を引き継ぐ。今回は新たにBlenderで風車、取水ポンプ、集電タワー、中央棟、近代化後の住宅を制作した。

## 遊べる流れ

風待ちの丘と中央地区が加わった5地区を俯瞰できる。開始時にTomoは風車、Shellはポンプ、Renは集電塔、Miaはカフェの用事を始める。現地で作業すると羽根が回り、送電線に灯りが走り、水が中央へ流れる。

中央の更新には電力・水・記録と、設備を動かす住民が必要。最初の二つの記録は昔の地図と街灯点検。住民との会話は話した本人が持ち、中央まで運んで初めて次の更新に使われる。言葉を繰り返し送っても、同じ内容は重複計上しない。

| 段階 | 街の見た目 | 記録 |
|---|---|---|
| 0 | 風車・ポンプ・塔を再開。低い中央棟 | 街にもともとあった記録 |
| 1 | 道に白い街灯が増える | 古い記録だけではここまで |
| 2 | 中央棟と最初の住宅が増築される | 実際に届いた人間の会話 |
| 3 | 川沿いに背の高い住宅が増える | 別の会話の記録 |

電力と水の必要量は段階ごとに増える。中央の窓に出る言葉は、届いて処理されたプレイヤーの会話そのもの。元の建物やキャラクターは削除せず、明るい窓と新しい建物が増えていく。

## 関わり方

- 施設の名前や「中央棟を見る」をクリックして、設備と流れを確認。「施設のそばへ降りる」で現地へ。
- 地上で施設の近くにいると、F／画面下のボタンで端末を開ける。風車の停止・再開、取水の停止・再開、街と中央への配電、中央の更新停止・再開を操作できる。
- Mで俯瞰に戻る。住民への追従、そばへの移動、目線を借りて歩く操作も継続。借りている間はその住民の仕事が止まる。
- 会話でも「風車を止めて」「街の暮らしに電力を分けて」などを相談できる。住民が選んだ操作は、本人が設備まで移動してから反映される。
- 「この話は二人だけにして」「中央には送らないで」で、その住民の未配達の記録を取り下げ、以後も中央へ届けなくなる。既に届いた記録を遡って消す操作ではない。「これからは送っていい」で再開。
- 中央棟へ実際に行くと、誰がどの言葉を届けたかを読める。別の住民に話した未配達の会話を、全住民のプロンプトへ一括共有しない。

## AIとゲームの境界

API接続時、住民は個人の願い・記憶・知っている街の事実をもとに、発言、次の用事、会話を共有するかを構造化出力で選ぶ。実行可能な用事だけをサーバーで受け付け、移動と資源の状態が実際の結果を決める。停止中に自動判断が勝手に設備を再開しないよう、運転方針の変更はプレイヤーとの会話または現地操作から行う。

中央モデルの「学習」は、この試作では資源を消費するゲーム内の進行として表現している。LLMの重みを追加学習したり、実際の巨大モデルを訓練したりするものではない。中央の建設計画と段階は設計済み。fal.ai、Replicateへの追加接続は行っていない。

中央棟にはRealtime APIによる音声会話を追加した。現在の資源・設備・配達済みの記録に基づいて返答し、明確に頼まれたときは更新の停止／再開を実行する。住民の非公開の記憶は中央に渡さない。中央への直接の発言は、現状では近代化に使う記録には加算しない。文字入力も使える。住民の会話・判断は `.env` から接続した `gpt-5.6-luna`、音声は `gpt-realtime-mini`。

住民は中央にそれぞれ違う期待を持つ。Miaは帰った人ともまた話せること、Renは人間の理解、Tomoは更新後も自分の居場所があること、Shellは今ある暮らしの維持。真相を会話のたびに作り変えず、知っている範囲を個別に渡す。

## アセットと実装

- 再生成: `Blender --background --python scripts/build-infrastructure.py`
- 編集用: `art/infrastructure/*.blend`
- 配信するモデル: `assets/infrastructure/*.glb`。外部依存を埋め込み、`manifest.json`に出所・生成スクリプト・SHA-256を記録。
- `Rotor`は風車とポンプの回転軸、`UpperWorks`は中央棟の増築部分。建設予定地の衝突領域は最初から確保する。
- 状態と資源: `server/infrastructure.mjs`。移動と資源消費は別管理で、実際に到着してから仕事が進む。
- 描画・操作: `src/infrastructure-world.js`、`src/infrastructure-view.js`。
- 進行と未配達の記録は既存のセーブに含める。旧バージョンの川辺の進行を消さずに新しい設備を追加する。

## 検証

`npm test`。現地到着、資源の不足、記録の運搬、共有の取り下げ、重複の排除、処理途中の停止と再開、旧セーブの移行、施設間の経路、Blenderアセットの整合性を確認する。従来の記憶・関係・会話・保存・川辺の共同作業の検証も残す。

確認結果：45件の自動テストが成功。Chromeで風車の停止・再開、住民による記録の運搬、3段階目までの増築、中央の受付への会話原文の反映を確認。実APIでMiaとの会話と「中央には送らない」というお願いへの返答も確認した。中央ではRealtimeの音声出力・字幕・会話からの更新停止、Lunaの文字会話からの更新再開を確認。入力マイクの実際の発話は未検証。
