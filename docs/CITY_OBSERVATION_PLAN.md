# 街を見渡し、誰かの生活に入る

2026-09-13。広い街で住民が自分の用事を進め、協力し、プレイヤーが気になる出来事に関わる方向の最初の実装。

## 活かすもの

陽菜が用意したMia・Ren・Tomo・ShellのオリジナルBlenderモデル、表情としぐさ、家具・家・植栽の素材、暖かい灯りと青い夜の雰囲気を引き継ぐ。既存のGLB・Blenderファイルや素材のライセンスは変更しない。

遊びの中心は「街を見渡す → 気になる住民を追う → その目線で事情を知る／会話で関わる → 街に戻ってその後を見る」。住民がプレイヤーの入力を待ち続けず、自分の用事を進めることを優先する。

## 今回遊べる範囲

- 灯りの広場、川辺の庭、木立の工房の3地区。既存の家・木・ベンチ等を再利用し、静的なモデルをインスタンス化。Lab・Libraryの既存の室内も残す。
- 俯瞰の移動・ズーム、地区への移動、住民への追従。出来事の表示をクリックすると現場を見られる。
- 住民のそばへ降りる／目線を借りて歩く。目線を返すと住民の自律移動が再開する。借りている間は本人の作業が自動で進まない。
- 川辺の配線調査 → 部品の収集・運搬 → 二人で修理。ランタンを運んで仮の灯りを作る別の方法もある。
- 二箱の本を届け、灯りのある川辺で二人が読書席を準備する。完成物は場に残る。
- プレイヤーが関わらなくても住民が用事を選ぶ。API接続時は個人の願い・記憶・公開された街の状態をもとにOpenAIが選択。未接続時は工程を遊べるデモ判断。
- 会話の構造化出力に、発言と本人の次の行動を含める。サーバーが現在実行できる行動か検証し、通ったものだけを移動・運搬・作業に反映。
- 作業の当事者に出来事が記憶され、共同作業を終えた二人の関係が変わる。公開掲示で分かる情報と、個人の会話の記憶を区別する。
- 街の状態、個々の用事、持ち物、位置を既存のセーブへ保存。APIキーは保存しない。

## 実装上の境界

今回の出来事と行動の種類は設計された小さな枠であり、AIが任意のゲーム機能や3Dオブジェクトを実装する仕組みではない。目線を借りる機能も、他人になりすまして関係を操作するシステムではなく、住民の体を一時的に操作して返す体験。

移動と衝突はクライアント、仕事と持ち物の状態はサーバーが担当する。仕事は報告された位置が作業地点に近い場合だけ進む。これはローカル一人用の実装で、対戦用の不正防止を目的とした位置検証ではない。

シミュレーションはゲーム画面を開いている間に進む。ブラウザを閉じた間の生活や、全員が常時LLMで考える仕組みは含まない。自律判断と会話は既存の接続ごと120回のAPI上限を共有する。

## 次に厚くする部分

1. Realtime APIで、歩きながら住民に声をかける。いまの行動の検証と記憶を共用し、音声で約束したことと実際の状態を一致させる。会場で音声が使えない場合も文字入力を使えるようにする。
2. fal.ai／Replicateを、住民が作る看板・音楽・記念品などへ接続。生成は背景で行い、完成した成果物を街に残す。既存のキャラクターと街の雰囲気を揃える。
3. 住民と地区を増やす。仕事、充電、場所の取り合い、物の貸し借りなどを共通の状態として持たせ、出来事が互いに影響する範囲を広げる。
4. 気になる住民の出来事を後から追える履歴、英語表示、プレイ動画と提出用説明を整える。

## 確かめること

説明なしに「何か起きている」と気づいて住民を選ぶか。本人の事情を知って、自分から提案したくなるか。目線を返した後、その住民が何をするか見届けたくなるか。

テストは到着前の作業禁止、借りた目線での自動進行停止、持ち物の運搬、二人の共同作業、別の解決方法、AIの不可能な行動の拒否、生成中に状態が変わる場合、経路の衝突回避、HTTPセッション分離を確認する。既存の記憶・保存・アセット検証も継続する。

2026-09-13の確認：`npm test`は31件成功。Chromeで地区をまたぐ自律移動、共同作業の完成、目線を借りて歩く／返す操作、サーバー再起動後の続きからの再開を確認。実APIの自由会話でTomoにカフェのテラスを整える提案をし、返答と行き先が変わることも確認した。住民が考えている途中に話しかけた場合は、判断が終わるのを待って会話を始める。
